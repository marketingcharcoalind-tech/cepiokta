## 6. Book Stability Diagnostic

Tujuan diagnostic: mengukur apakah perubahan order book setelah entry dapat mendeteksi loss dan berapa banyak kemenangan yang ikut terflag.

File utama:

- `src/btcbot/backtest/book_stability_diagnostics.py`
- `tests/backtest/test_book_stability_diagnostics.py`
- `BOOK_STABILITY_DIAGNOSTIC_GUIDE.md`
- `BOOK_STABILITY_DIAGNOSTIC_SUMMARY.md`

### Runtime bugs yang diperbaiki

1. `StrategyParams(t_entry=...)` salah. Field benar `t_entry_sec`, config dibangun via `ReplayConfig.from_settings()` dan `dataclasses.replace()`.
2. Token mapping memakai `token_id.endswith("UP")`, padahal token ID Polymarket bukan suffix UP/DOWN. Diganti exact equality memakai `round.token_id_up/down`.
3. Snapshot pre-entry ikut terhitung. Filter diperbaiki agar mulai dari entry.
4. Lifecycle Store salah memakai `Store(args.db) + connect()`. Diganti `await Store.open(args.db)`.
5. `reconstruct_ticks()` dipanggil dengan signature salah. Diganti streaming `load_round_replays()`.
6. Slotted dataclass memakai `metrics.__dict__`. Diganti `dataclasses.replace()`.
7. Entry timestamp awalnya approximation dari signal. Replay observability kemudian mengekspose timestamp decision dan fill asli.

## 7. Latency Audit dan Temuan G1 Blocker

### 7.1 Masalah model tick latency

Replay historis memakai:

```python
requested_index = decision_index + latency_ticks
actual_index = min(requested_index, n - 1)
```

Satu tick adalah satu event book, bukan durasi waktu tetap. Dua token dapat update dengan timestamp sama atau terpisah beberapa milidetik/detik. Ini membuat `latency_ticks=1` tidak representatif sebagai network/execution latency.

## 8. Time-Based Latency Implementation

Implementasi dibagi menjadi empat sub-task agar aman.

### Sub-Task 1: Core infrastructure

Commit `9efe0b2`.

Ditambahkan:

- Settings:
  - `BACKTEST_LATENCY_MODE=ticks|time`
  - `BACKTEST_LATENCY_TICKS=1`
  - `BACKTEST_LATENCY_MS=100`
- `ReplayConfig.latency_mode`, `latency_ticks`, `latency_ms`
- frozen slotted `ExecutionSelection`
- pure `select_execution_tick()`

Time mode:

- `requested_execution_ts = decision_ts + latency_ms`
- pilih tick pertama dengan `tick.ts >= requested_execution_ts`
- jika tidak ada future tick, `no_future_tick=True`, tidak clamp dan tidak invent liquidity

### Sub-Task 2: ReplayEngine integration

Commits:

- `89a028b`: integrasi awal entry/hedge/exit
- `1137106`: perbaikan false O(log n)
- `9f05a51`: test hardening awal, tetapi masih vacuous
- `be739d1`: test suite diganti langsung di GitHub agar non-vacuous

ReplayEngine sekarang:

- validasi timestamps sekali per ronde
- membangun `tick_timestamps = tuple(t.ts for t in ticks)` sekali per ronde
- tick mode O(1)
- time mode menggunakan `bisect_left` pada tuple precomputed, O(log n) per decision
- selector dipakai untuk entry, hedge, dan exit
- no-future time mode tidak clamp, tidak same-tick fallback, dan menambah counter
- observability menyimpan mode, configured latency, indices, timestamps, realized latency, overshoot, exact successful order limit price, serta no-future counters
- default tetap tick mode untuk backward compatibility
- strategy, fee, sizing, settlement, dan DB schema tidak diubah
