## 8. Time-Based Latency Implementation

The work is deliberately split into four sub-tasks.

### Sub-Task 1: core selector and config — complete

Commit `9efe0b2`:

- added `BACKTEST_LATENCY_MODE=ticks|time`
- preserved `BACKTEST_LATENCY_TICKS=1`
- added `BACKTEST_LATENCY_MS=100`
- extended `ReplayConfig`
- added frozen/slotted `ExecutionSelection`
- added pure `select_execution_tick()`
- time mode chooses first recorded tick at or after `decision_ts + latency_ms`
- time mode fails closed when no future tick exists
- tick mode preserves historical clamping behavior

### Sub-Task 2: ReplayEngine integration — complete in production code

Commits:

- `89a028b`: initial engine integration
- `1137106`: corrected false O(log n) implementation

Current production behavior:

- ticks validated once per round
- timestamp tuple built once per round
- tick mode selection O(1)
- time mode uses `bisect_left` on precomputed timestamps, O(log n) per decision
- centralized selector used for entry, hedge, and exit
- no-future time-mode attempts do not clamp or fill
- no-future counters added for entry/hedge/exit
- successful entry observability includes exact order limit price
- default remains historical tick mode

### Sub-Task 2 test hardening

Commit `be739d1` replaces the file with non-vacuous tests that force:

- no-future entry fail-closed behavior

- hedge execution and hedge no-future behavior

This is Phase 1 research, not Phase 2. It may be implemented after the latency audit/time-sensitivity work is stable.

- detect opportunities where executable cost of both outcomes is below settlement value after costs
