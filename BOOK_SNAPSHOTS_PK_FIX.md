# Book Snapshots PRIMARY KEY Fix

**Date**: 2026-07-06  
**Issue**: De-dup historis pakai `CREATE TABLE AS SELECT` merusak kolom PRIMARY KEY  
**Impact**: `book_snapshots.id` berhenti jadi INTEGER PRIMARY KEY AUTOINCREMENT, baris baru dapat `id=NULL`  
**Consequence**: De-dup berbasis `id` menghapus ~256 ronde (372 → 116)

---

## Root Cause

Prosedur de-dup yang pernah dijalankan menggunakan `CREATE TABLE AS SELECT`:

```sql
-- ❌ WRONG - This BREAKS PRIMARY KEY AUTOINCREMENT
CREATE TABLE book_snapshots_new AS 
SELECT DISTINCT * FROM book_snapshots;

DROP TABLE book_snapshots;
ALTER TABLE book_snapshots_new RENAME TO book_snapshots;
```

**Problem**: `CREATE TABLE AS SELECT` creates a table WITHOUT constraints (no PRIMARY KEY, no AUTOINCREMENT). Subsequent INSERTs get `id=NULL`.

**Correct Code**: The schema in `src/btcbot/data/store.py` is already correct:
```python
CREATE TABLE IF NOT EXISTS book_snapshots (
    id INTEGER PRIMARY KEY AUTOINCREMENT,  # ✅ This is correct
    ...
)
```

**But**: The live DB `~/cepiokta/btcbot.db` was corrupted by the bad de-dup procedure.

## Fix Procedure (SAFE - Works on Backup)

### Option A: Automated Script (Recommended)

```bash
cd ~/cepiokta
bash scripts/fix_book_snapshots_pk.sh
```

**What it does**:
1. Creates backup: `btcbot.backup.YYYYMMDD_HHMMSS.db`
2. Pre-check: counts distinct `round_no` BEFORE
3. Rebuilds table with correct PRIMARY KEY in the backup
4. Post-check: verifies `round_no` count unchanged, no NULL ids
5. Shows instructions for replacing live DB

**Safety**: Works on BACKUP file, not live DB (avoids 'database is locked')

### Option B: Manual Steps

```bash
cd ~/cepiokta

# 1. Backup
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
cp btcbot.db btcbot.backup.$TIMESTAMP.db

# 2. Pre-check
sqlite3 btcbot.backup.$TIMESTAMP.db "SELECT COUNT(DISTINCT round_no) FROM book_snapshots;"
# Note the number (e.g., 372)

# 3. Rebuild with correct schema
sqlite3 btcbot.backup.$TIMESTAMP.db <<'EOF'
BEGIN TRANSACTION;

CREATE TABLE book_snapshots_new (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    round_no INTEGER,
    token_id TEXT,
    ts TEXT,
    best_bid TEXT,
    best_ask TEXT,
    bid_depth TEXT,
    ask_depth TEXT,
    gap INTEGER NOT NULL DEFAULT 0,
    raw TEXT,
    mode TEXT
);

-- Copy data (id regenerated by AUTOINCREMENT)
INSERT INTO book_snapshots_new (
    round_no, token_id, ts, best_bid, best_ask, bid_depth,
    ask_depth, gap, raw, mode
)
SELECT 
    round_no, token_id, ts, best_bid, best_ask, bid_depth,
    ask_depth, gap, raw, mode
FROM book_snapshots
ORDER BY COALESCE(id, 999999999999999), round_no, ts;

DROP TABLE book_snapshots;
ALTER TABLE book_snapshots_new RENAME TO book_snapshots;
CREATE INDEX idx_book_snapshots_round_ts ON book_snapshots(round_no, ts);

COMMIT;
EOF

# 4. Post-check (MUST match pre-check!)
sqlite3 btcbot.backup.$TIMESTAMP.db "SELECT COUNT(DISTINCT round_no) FROM book_snapshots;"
sqlite3 btcbot.backup.$TIMESTAMP.db "SELECT COUNT(*) FROM book_snapshots WHERE id IS NULL;"
# Should be: same round count, 0 NULL ids

# 5. Verify schema
sqlite3 btcbot.backup.$TIMESTAMP.db "SELECT sql FROM sqlite_master WHERE name='book_snapshots';"
# Should contain "INTEGER PRIMARY KEY AUTOINCREMENT"
```

## Prevention: Never Use CREATE TABLE AS SELECT

**Rule**: NEVER use `CREATE TABLE AS SELECT` for tables with PRIMARY KEY / AUTOINCREMENT.

**Correct de-dup procedure**:

```sql
-- ✅ CORRECT: DELETE duplicates, keep PK intact
DELETE FROM book_snapshots
WHERE id NOT IN (
    SELECT MIN(id)
    FROM book_snapshots
    GROUP BY round_no, token_id, ts, best_bid, best_ask, 
             bid_depth, ask_depth, gap, mode
);
```

**If rebuild needed (e.g., schema change)**:

```sql
-- ✅ CORRECT: INSERT INTO with explicit schema
CREATE TABLE book_snapshots_new (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ... (full schema)
);

INSERT INTO book_snapshots_new (col1, col2, ...)  -- NOT including id
SELECT col1, col2, ... FROM book_snapshots ORDER BY id;

DROP TABLE book_snapshots;
ALTER TABLE book_snapshots_new RENAME TO book_snapshots;
```
