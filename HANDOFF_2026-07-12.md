## 1. Ringkasan Eksekutif

Proyek adalah bot Polymarket BTC Up/Down 5 menit. Urutan aman proyek tetap:

```text
readonly data -> backtest/replay -> paper trading -> live micro -> scale
```

Dua jalur riset Fase 1 telah diselesaikan:

1. **Strategi directional fair-value taker**
   - Kandidat defensif: `t_entry=60`, `delta_threshold=50`, `min_price=0.96`, `max_price=0.99`.
   - Kandidat tetap positif setelah fee, slippage, dan latency berbasis waktu sampai 1000 ms.
   - Positif pada ALL5, OLD4, dan NEW split.
   - Keputusan: **G1 LANJUT ke Phase 2 paper trading**, tetapi **belum live**.

2. **Pure intra-market lock-pair arbitrage, Prompt 1.7**
   - Detector read-only telah dikoding dan diuji.
   - Dataset menunjukkan 462 episode opportunity, tetapi LVCF-implied duration p25/median/p75 = `0/0/0 ms`, maksimum `2 ms`.
   - Ini praktis tidak dapat dieksekusi dari VPS retail.
   - Depth dataset adalah aggregate side depth, bukan exact best-level depth, sehingga theoretical PnL `$504.46` hanya upper-bound proxy.
   - Keputusan: **jangan lanjut ke paper/live pure-arb sekarang**.

Langkah berikutnya adalah **PROMPT 2.1 Risk Manager** untuk jalur directional paper trading.

## 6. Latency Audit dan Perbaikan Model


41 zero-latency entries menyumbang `+$6.38`, sehingga baseline lama tidak cukup untuk G1.

### Time-based latency implementation

Ditambahkan:

```text
BACKTEST_LATENCY_MODE=ticks|time
BACKTEST_LATENCY_TICKS=1
BACKTEST_LATENCY_MS=100
```

ReplayEngine kini mendukung:

- tick mode backward-compatible
- time mode dengan `decision_ts + latency_ms`
- binary search pada tuple timestamp precomputed, true O(log n)
- selector dipakai untuk entry, hedge, dan exit
- no-future time mode fail-closed, tidak clamp dan tidak invent liquidity
- observability exact indices, timestamps, realized latency, overshoot, no-future counters

- output secara eksplisit menyebut `LVCF-implied duration`

- theoretical PnL = upper bound sebelum two-leg execution risk
